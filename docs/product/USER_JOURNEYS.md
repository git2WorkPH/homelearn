# User journeys

Status: Draft; see [acceptance criteria](../requirements/ACCEPTANCE_CRITERIA.md).

1. A parent registers, creates a family, adds two synthetic learners and saves onboarding progress. On returning, completed steps persist.
2. The parent selects Guided Mode, reviews starter goals, adjusts per-learner preferences and explicitly creates a weekly plan. Suggestions never activate themselves.
3. An experienced parent selects Independent Mode, defines custom goals and leaves some activities unscheduled.
4. Two learners share an activity. Each receives separate observations and outcome judgements; one learner's progress does not change the other's.
5. An unexpected learning experience is recorded directly, with date, learner and observation, without requiring a planned activity.
6. The parent uploads evidence, waits for validation, links it to records and reviews an authorised portfolio.
7. A summary distinguishes planned, completed, observed and demonstrated learning and exports to PDF with evidence references.
8. Switching modes changes guidance without deleting or rewriting educational records.

Error journeys include expired sessions, conflicting edits, rejected uploads, unavailable storage and attempted access to another family's identifiers. Preserve entered work where safe and provide actionable, non-sensitive error messages.
